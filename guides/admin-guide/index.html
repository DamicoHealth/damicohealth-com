Admin vs Standard device roles

Every device in your organization is one of two roles:

  • Admin — can edit presets and forms, manage the cloud connection, run backups, and generate donor reports. Typically the team lead's device or the backend laptop.
  • Standard — can create encounters, view records, and run analytics. Cannot change configuration or the formulary — those editors show up read-only, and the encounter form uses whatever the admin device set up.

The first device that creates the organization (via the New Organization wizard) automatically becomes the admin. Any other device can become admin by claiming admin access with the admin password (next section). A device can also step down again with Admin → Admin Access → Release Admin Role.

Claiming admin access & the admin password

The admin password is set once, on the admin device, when you first create the organization (the wizard's "Set Admin Password" step). Any Standard device can then use that password to promote itself to Admin — there is no per-device "promote" list.

To make another device an admin:

  1. On that device, open the Admin tab.
  2. Under Admin Access, type the admin password into Admin Password.
  3. Tap Claim Admin Access. The device becomes Admin and the preset editors unlock.

To change the password (from any admin device): Admin → Admin Access → Change Admin Password.

Important

The admin password is stored on the device, not synced. If you forget it, promote a device using another device that is already an admin, or reset it from an admin device via Change Admin Password. If every admin device has lost it, email md@damicohealth.org.

Customizing presets

Presets live in the Options tab (editable only on an Admin device). They control what shows up as one-tap buttons on the encounter form. Changes save automatically and sync to every device. Investing 30 minutes in good presets pays off across hundreds of patient encounters.

Sites / Communities

Each clinic location or community your team works at. A site is just a name — tap + Add Site, type it, and save. Sites appear in the Site picker on every encounter form. (Removing a site that older records reference doesn't change those records — the app warns you and keeps their site label.)

Physicians

The clinicians on your team. A physician is just a name — tap + Add Physician and type it (e.g. "Dr. Smith"). Names appear as one-tap buttons in the encounter's Physician block.

Formulary (medications)

Your medication list, which feeds the medication builder and Rx presets. For each medication (+ Add Medication) you set:

  • Medication Name (e.g. "Amoxicillin 500mg")
  • Default Dose (e.g. "500mg") — pre-fills when the drug is picked
  • Unit — tabs, caps, mg, ml, g, IU, vial, sachet, drops, cream
  • Category — Antibiotics, Antimalarials, Analgesics, etc. (used to group the drug picker)
  • Controlled Substance — a checkbox that flags the drug with a warning marker wherever it appears

The app does not track stock levels or separate pediatric dosing — dose is adjusted per patient in the encounter's medication builder.

Procedures

The procedures your team performs — incision & drainage, suturing, dressing change, foreign body removal, etc. A procedure is just a name (+ Add Procedure); it appears as a one-tap button in the encounter's Procedures block.

Chief complaints

Common presenting complaints — fever, abdominal pain, cough, rash. Each is a single name and shows as a one-tap button in the Chief Concern section. Add ones specific to your program (e.g. snake bite, road traffic injury).

Diagnosis presets

The diagnoses your team commonly makes. Each preset is a single diagnosis name (+ Add Diagnosis) that becomes a one-tap button next to the free-text Working Diagnosis field. (An optional ICD-10 code picker is available on the encounter form itself, separate from these presets.)

Lab tests (custom POS/NEG or numeric)

Add the labs your program runs (+ Add Lab Test). For each:

  • Test Name
  • Result Type — either POS / NEG or Numeric Value
  • For numeric tests, an optional Unit (e.g. mg/dL, g/dL, mmol/L)

Built-in tests can't be edited but can be hidden; custom tests you add can be renamed or removed. Urinalysis is a fixed dipstick panel on the encounter form, not a lab-test entry here.

Rx presets (prescription bundles)

One of the biggest time savers. An Rx preset bundles one or more medications — each with a drug (from your formulary), dose, frequency, and duration — into a single one-tap button, plus optional treatment notes. Build them in Options → Rx Presets:

  1. Tap + Add Rx Preset and give it a name (e.g. "H. pylori Triple Therapy").
  2. Add one or more medication lines: pick the drug, set dose, frequency, and duration.
  3. Optionally add treatment notes, then save. The app builds a readable prescription summary automatically.

On the encounter form, tapping a preset drops the whole bundle into the medication builder, where you can still adjust it per patient.

Referral types

The kinds of referrals your team makes — surgery, hospital transfer, follow-up clinic, OB/GYN, dental, ophthalmology, etc. Each type is a single name and appears as a one-tap button in the encounter's Referral block; picking one reveals an optional Scheduled Date. There is no separate "destination" field. (The built-in None option can't be removed.)

Building custom form sections

Beyond presets, the Encounter Forms builder at the top of Options lets you add your own sections and questions, and even create multiple encounter forms (e.g. General, Surgery, Dental). This is where you add anything the built-in form doesn't cover — for example extra vitals like heart rate, respiratory rate, or SpO2 — as custom fields. When more than one form is active, clinicians pick which to use when they start a new encounter. Changes save automatically and sync to every device.

Show/hide presets without deleting

Procedures, chief complaints, diagnosis presets, Rx presets, referral types, and lab tests each have an eye icon next to their edit/delete buttons. Tap it to hide that preset from the encounter form without deleting it — useful for seasonal items (e.g. antimalarials only relevant on certain trips) or items you might bring back. Hidden rows stay in the editor, just dimmed.

Tip

Prefer hiding over deleting for anything already used in encounters. Hiding keeps the preset out of the way while preserving the labels on historical records. (Sites and physicians don't have an eye icon — if you remove one that older records use, the app warns you first and leaves those records' labels untouched.)

Cloud sync with your own Supabase

To share records across devices and keep an off-device copy, connect the app to a free Supabase project that your organization owns. The full walkthrough — creating the project and running the setup SQL — is in the Setup Guide.

  1. Set this up during the first-run wizard ("New Organization"), or later from Admin → Cloud Connection (a device that started in Standalone mode gets a Connect to Cloud button here).
  2. Paste your Supabase Project URL and anon key (from Supabase → Settings → API) under Edit Connection Settings.
  3. Save & Connect. The app verifies the connection and starts syncing.

Once connected, the Admin → Cloud Connection section shows the current status, and the top-bar indicator shows Connected / Syncing / Error plus how many records are still pending and how long ago the last sync ran.

Use the anon / publishable key

Never enter or share your Supabase service_role / secret key — only the anon (publishable) key, which is the one meant for the app.

Adding team devices

Every other phone, tablet, or laptop joins by using the same Supabase URL and anon key as the first device.

  1. Install the app on the new device and open it.
  2. In the setup wizard, choose Join Existing Setup.
  3. Paste your Supabase URL and anon key — the device pulls down your presets and history automatically. It joins as a Standard device; promote it later if needed (see Claiming admin access).
Keep your credentials handy — and private

Your Supabase URL + anon key are the "key" to your shared data. Keep them where your team can find them, and don't post them publicly.

How sync works

Sync is automatic and always on whenever the device has internet — there is no manual/automatic mode setting and no separate sync log to manage. Each device pushes its own new and edited records to your Supabase and pulls everyone else's, so every device converges on the same set of records.

  • The app syncs on a light schedule and on the events that matter: shortly after you save or delete, when the device reconnects, and when you bring the app back to the foreground.
  • You can force a sync right now by tapping the sync indicator in the top bar, or with Admin → Cloud Connection → Sync Now.
  • When a device is offline, records save locally and sync the next time it's online — nothing is lost.
  • Conflicts use last-write-wins, with the server's timestamp as the authority; a local edit that hasn't synced yet is always kept.
End-of-day habit

You don't need to "run" sync — but it's still worth gathering devices somewhere with reliable wifi at the end of a clinic day and tapping the sync indicator on each, so everything is up in your Supabase before anyone travels or powers down.

Backups

Whether or not you use cloud sync, download a backup at least once per clinic day. From Admin → Backup & Restore:

  1. Tap Download Backup
  2. Save the .json file — to your Files app, AirDrop to a teammate, or copy it to a laptop
  3. The file contains all records and settings

Restore on any device via Admin → Backup & Restore → Restore from File. Restoring merges into the device — it never deletes existing records.

Why backups matter

A downloaded file is the one copy a device can never clear on its own — especially important in offline-only mode, where it's your only safety net. On iPads especially, treat a daily backup (or cloud sync) as your real safety net.

Moving to a new iPad / replacing a device

When you retire, lose, or replace a device, here's how to carry the data over.

If you use cloud sync

  1. On the old device (if you still have it), open the app while online and tap the sync indicator so its latest records are up in Supabase.
  2. Install the app on the new device and open it.
  3. In the setup wizard, choose Join Existing Setup and paste the same Supabase URL and anon key your team uses.
  4. Name the device. It pulls down all records and presets on the first sync. Promote it to Admin if it needs to edit configuration.

If you are offline-only (Standalone)

  1. On the old device, open Admin → Backup & Restore → Download Backup and save the .json file somewhere you can get to it (Files, AirDrop, email, a laptop).
  2. Install and open the app on the new device; in the wizard, choose Standalone (Offline Only) and name the device.
  3. Open Admin → Backup & Restore → Restore from File and pick the backup file. Records and settings are merged in.
Don't wipe the old device until you've confirmed the new one

Open the new device and check that the expected records are present (and, for cloud teams, that the top-bar indicator shows Connected) before erasing or handing off the old one.

Generating donor reports

The donor report is a one-tap PDF summary of activity, built from whatever filters are set on the Analytics screen. From Analytics:

  1. Set the From / To dates and, if you want, a Site or Sex filter at the top of the screen.
  2. Tap Generate Donor Report.
  3. The app produces a formatted PDF covering the filtered period — total encounters and unique patients, age and sex breakdown, sites, top 10 diagnoses, lab positivity, top medications dispensed, and a referrals summary.

There's no separate "choose sections" dialog or saved report templates — the report always includes those sections for the current filter. For raw data, use Export CSV on the same screen and analyze it in any spreadsheet or stats tool.
